## F1. embedmd が入らない — Go が無かった

- **種別**: beginner
- **何をしようとしたか**: 教材が実ファイルからコードを引用できるように embedmd を入れる
- **何が起きたか**: `go` コマンドが無い。embedmd は Go 製で、npm では入らない
- **どう気づいたか**: `which go` が空だった
- **どう抜けたか**: `brew install go`（約1分）→ `go install github.com/campoy/embedmd@latest`
- **教材への活かし方**: **学習者には出さない**。embedmd は制作側の道具で、教材の手順には登場しない。
  ただし制作環境を別のマシンへ移すときに同じ所で止まるため、制作手順書に残す

## F2. 禁止表現の辞書が、書いた時点では動く気になっていた

- **種別**: ai-artifact
- **何をしようとしたか**: 関西弁・誇大表現・AI構文を textlint で機械的に止める
- **何が起きたか**: 9パターン中 **3件を取りこぼした**
  - 「動いとらん」→ 辞書に `しとらん` と書いており、活用の頭を固定していた
  - 「作っていきましょう」→ 辞書に `していきましょう` と書いていた
  - 「誰でも簡単に」→ 直前のルールが同じ行を先に食っていて、独立に発火するか確かめられていなかった
- **どう気づいたか**: 禁止パターンを埋め込んだテスト用の章を作って食わせた
- **どう抜けたか**: 正規表現を活用形に依存しない形へ緩め、行を分けて再テストした（9/9 検出）
- **教材への活かし方**: これは**制作工程の教訓**であり、章の内容ではない。
  10 §3 の G2 に「辞書を足すたびに検知テストを回す」として反映済み

## F3. `embedmd -d` の終了コードが 1 ではなく 2 だった

- **種別**: unobserved（誰も観測していなかった前提）
- **何をしようとしたか**: 引用元と教材のズレを CI の合否にする
- **何が起きたか**: ズレを作って走らせたら **exit=2** が返った。
  合否を `exit 1` と書いていたら**ズレを見逃していた**
- **どう気づいたか**: 実際にズレを作って終了コードを表示した
- **どう抜けたか**: 判定を「非ゼロなら FAIL」に直した
- **教材への活かし方**: 制作側の話。10 §4 の G5 に明記済み

## F4. ディスクが満杯で、コマンドの出力すら書けなくなった

- **種別**: beginner
- **何をしようとしたか**: Expo プロジェクトを作って依存を入れる
- **何が起きたか**: `npm install` が途中で落ち、その後 `echo` すら
  `write error: no space left on device` を出した。空き **1.0GB / 460GB**
- **どう気づいたか**: エラーメッセージが「no space left on device」と明示していた
- **どう抜けたか**: 再取得できるキャッシュだけを消した（`~/.npm/_npx` と `~/.cache/uv`）。
  作業中の資産（他プロジェクトのシミュレータ・Android SDK・リポジトリ）には触っていない。
  空きは 9.1GB に戻った
- **教材への活かし方**: ★**これは教材にそのまま載る**。
  Expo の `node_modules` は約327MB あり、初心者の手元でも同じことが起きうる。
  「なぜか途中で止まる」で終わらせず、**エラーメッセージの1行目を読む**という
  一番大事な習慣を教える題材として最適。A0 の「詰まったときの読み方」の章で使う

## F5. ポート 8081 が別の作業で使われていた

- **種別**: beginner
- **何をしようとしたか**: `npx expo start --ios` で開発サーバーを立てる
- **何が起きたか**: `Port 8081 is running mypappy in another window` と出て止まった。
  さらに 8082 は別のアプリ（OrbStack）が使っていた
- **どう気づいたか**: Expo が**どのプロセスが使っているかまで表示してくれた**
- **どう抜けたか**: 空いているポートを探して `--port 8090` を明示した。
  **他人が使っているプロセスは止めていない**
- **教材への活かし方**: ★**これも教材に載る**。
  「ポートが使われている」は初心者が必ず1回は踏む。しかも
  「動いているものを止めれば解決する」と考えて他の作業を壊すのが典型的な事故。
  **止めるのではなく、空いている場所を使う**を最初に教える

## F6. Expo Go の開発者メニューが画面を覆い、消せなかった

- **種別**: unobserved
- **何をしようとしたか**: シミュレータ（iPhone 16 Pro / iOS 26.1）に最初の画面を出して確認する
- **何が起きたか**: アプリは動いていたが、Expo Go の初回案内シートが手前に出たままになった。
  この環境では画面をタップする手段が無く（画面操作の許可が下りていない）、
  アプリを入れ直しても設定ファイルを書き換えても案内が消えなかった
- **どう気づいたか**: 撮った画像に案内シートが写り込み、その裏に目的の文字がぼやけて見えていた
- **どう抜けたか**: アプリの起動時に設定値を直接渡す形（`simctl launch` の引数）で案内を終了済みにした
- **教材への活かし方**: **学習者には出さない**。学習者は指で1回触れば消える。
  これは自動で確認する制作側だけが踏む詰まりなので、制作手順書に残す

## F7. web に出すには追加の部品が2つ要った

- **種別**: unobserved（計画が「web は標準機能」とだけ把握していた）
- **何をしようとしたか**: 同じコードから web を出力する（計画の確信度70%の項目を潰す）
- **何が起きたか**: `expo export --platform web` が
  「`react-dom` と `react-native-web` が入っていない」と言って止まった。
  **Expo は web に出せるが、部品は最初から入っているわけではない**
- **どう気づいたか**: エラー文が入れるべき部品名と入れ方をそのまま書いていた
- **どう抜けたか**: `npx expo install react-dom react-native-web` を実行し、再度出力した。
  同じ `App.tsx` から web の画面が出た
- **教材への活かし方**: ★**パートD（Webでも動かす）の1章目にそのまま載る**。
  「同じコードが web でも動く」は本当だが、**1回だけ部品を足す手順が要る**。
  これを書かないと、パートDの冒頭で全員が同じ所で止まる

## F4-2. ディスクがまた満杯になった（F4 の再発）

- **種別**: beginner
- **何が起きたか**: 一度 9.1GB まで戻した空きが、作業中に 1.5GB まで減った
- **どう抜けたか**: npm の再取得可能なキャッシュだけを消して 2.8GB へ戻し、
  web の部品を入れた後は 4.4GB になった
- **教材への活かし方**: F4 と同じ章で扱う。**1回消せば終わりではなく、
  作業中に何度も起きる**という点を追記する

## F8. 別プロジェクトのアプリが同じ入口を取り合って、画面が止まった

- **種別**: unobserved
- **何をしようとしたか**: 2章目の「その場反映」をシミュレータで確かめる
- **何が起きたか**: `exp://` で開こうとしたら
  「"別アプリ" で開きますか?」という選択の窓が出て、そこから先へ進めなくなった。
  同じシミュレータに入っていた**別プロジェクトのアプリが同じ入口を登録していた**
- **どう気づいたか**: 画面写真に、目的の画面ではなく選択の窓が写っていた
- **どう抜けたか**: **別プロジェクトのアプリは消していない**。
  自分が起動したシミュレータを再起動して、残っていた窓を消した。その後は正しく開いた
- **教材への活かし方**: **学習者には出さない**。学習者の端末に別プロジェクトのアプリは無い。
  制作側が同じ機械で複数の案件を扱うときの話なので、制作手順書に残す
