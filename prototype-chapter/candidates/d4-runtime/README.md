# D4の章頭実装と実行境界の候補

NON_FORMAL_D4_RUNTIME_CANDIDATE。前段の終了状態とは別に、Authだけの19ソースから投稿画面を作る教材候補です。正式START、A5、D4/G6の合格は未判定です。

start/はAuth候補の追跡対象ソースだけを複製し、投稿画面は含みません。chapter-build.mdに全コードとApp変更箇所を載せます。start-manifest.jsonは既存brokerのpath-bound snapshot digestで開始19ソースを固定します。依存キャッシュ、private設定、資格情報は含めません。

実機接続とアカウント入力は制作側driverの責任です。モデルへ資格情報やprovider管理権限を渡す構成にはしません。固定操作や教材外補完を独立学習実走へ読み替えません。

部品の契約は、宣言された公開入力とtrusted bindingの照合、協調する制作側controller間の排他、レビュー済み本文のテキスト復元です。JWT署名の検証、処理中の強制中断、非協調クライアントの排除、独立学習の証明は含みません。公開keyの許容文字は本候補のbase64url形式に限定し、任意の将来形式を保証しません。

実機接続は制作側の専用driverで実行し、この公開候補には資格情報・接続設定・実機制御を含めません。限定pilotの実測は本文からの独立制作や正式合格とは別に記録します。leaseのdispatchは呼出前後で期限を確認し、期限を超えた操作を正常成功として返しません。ただし外部の副作用が既に発生している可能性があり、自動再試行やrollbackはしません。

Pythonのat-fork hookを通る協調controllerのforkが対象です。hookを通らないnative forkやsignal handler内のforkは本候補の運用契約外です。生存したまま停止した所有者のロックを期限だけで奪いません。

章はA→B→Aの操作、RPCのtrue/false/結果不明、再実施時の投稿再準備を説明します。Appの置換対象はrecovery分岐末尾の3行で、変更後は5行です。パスワード再設定側を保持し、外側の「プロフィール準備中」見出しは変更しません。本文は15コード345行を保持します。

`tools/d4_run_clock.py` は、制作側が新しく始めた作業のUTC時刻とLinuxのmonotonic経過時間を保存する部品（monotonicはOSのsuspend時間を含みません）です。章・開始ソース・manifest・判定条件のhashに結びつけ、成功した観測時刻も永続化します。中断した区間はOPENで残し、再試行として申告した区間は、終了した失敗区間に明示的に結びつけます。モデルと操作の区間が重なるため、区間合計は全経過時間ではありません。人の実働時間は未計測で、過去の作業時間を推定して埋めません。再起動でboot IDが変わった場合は継続を拒否します。同じrun IDの重複開始を防ぐ範囲は同一ledgerで、システム全体の一回限り実行や正式完了判定は未接続です。

`tools/verify_d4_origin.cjs` は、制作側が本文から復元したAppとRlsTrialを、生成結果と比較します。TypeScriptの構文木から出力を正規化し、空行などと、指定したRlsTrial importを先頭のimport群内で動かすことだけを許容します。文字列・JSXの空白・コメント・認証分岐などの変更は不一致として扱います。制作側は正解ソースをモデルへ渡さず、通常の型検査とは別に照合します。TypeScriptの入力パスには実体の絶対ディレクトリを指定します。構文の照合は、モデルの知識の由来や正式G6の隔離を証明しません。
