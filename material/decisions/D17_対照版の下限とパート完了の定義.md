## 1. D17 の決定

### [D17-1] 対照版を G3 の検査対象に入れる。除外をやめる

対照版に課すのは G3 の5検査（10:198-202）のうち **文体チェック・構造チェック・
方針同期チェック**の3つ。開始状態混入検査と開発ログ存在確認は章単位の検査であり、
本物側で1回課せば足りるので二重に課さない。
`g3-style.sh` の `[[ "$f" == *-plain.md ]] && continue` と、その理由を述べた
18-20行のコメントを撤去する。

**理由**: 除外の理由として書かれている「掛けると必ず落ちる」が実測で否定された
（§0.1、§0.3。現物4本すべて exit 0、検出器の生存も §0.2 で確認済み）。
文体ゲートが見るのは一文の長さ・弱い表現・助詞の重複・誇大表現・AI構文・
不採用スタック名であって、対話の有無ではない。手順書調に書くことと
これらを踏むことは別の事象である。

除外を残した場合に起きることの方が重い。10:210 で退屈度が G4 から外れて
G6 の比較評価へ一本化された結果、**面白さの合否はこの1経路しかない**。
その1経路の対戦相手が「文体ゲートを通っていない文章」でよいなら、
本物は文体で勝てる。勝敗が中身ではなく形式で決まる比較は、
§8 が絶対評価を捨てたのと同じ理由（測りたいものを測っていない）で捨てるべきものになる。

方針同期チェックを課す理由は別にある。対照版は本物と同じ内容を別の形で書いた文章なので、
不採用スタック名（NestJS 等）や登場人物名の取り違えを同じ確率で含みうる。
配布しない文書だから素通しでよい、とは言えない —
対照版の記述は G6 の読み手（文脈ゼロの実行体）が実際に読む文章である。

### [D17-2] 対照版は「本物から1要素だけを抜いた版」と定義し直し、1章2ラウンドを必須にする

対照版は次の2本を各章ごとに用意し、G6 read を2ラウンド走らせる。
どちらのラウンドも合否条件は現行どおり「本物が実行体の過半数で選ばれること」
（`g6-run.sh:157-171` の閾値ちょうどの再走扱いも現行どおり）。

| ラウンド | 対照版 | 抜く要素 |
|---|---|---|
| 1（粗い判別） | `g6/<章ID>/plain.md` | 対話を全部。手順書調に直す（現行 10:306 の定義そのまま） |
| 2（精密） | `g6/<章ID>/minus.md` | 対話は残す。**その章の開発ログで「教材に載せる価値: 高」とラベルされた詰まりの記述**だけを抜く |

各ファイルの先頭に、抜いた要素を1行のメタ行として書く（例:
`<!-- 抜いた要素: 価値高の詰まり2件（ディスク不足・ポート競合） -->`）。
ラウンド2の対象が0件の章（開発ログに「価値: 高」の詰まりが無い章）は、
ラウンド2を **N/A** で記録し、0件であることを G6RUN 受領証に残す。
省略ではなく明示の判定として残す（10:243 の N/A-PASS と同じ扱い）。

**理由**: ラウンド1だけでは合否が出ない。捨て試作でラウンド1相当の比較は
3/3 で本物が勝っており（道具検証の記録 §8 の Q5）、**一度も FAIL していない**。
§8 自身が「PASS しか出ない道具は、合否を判定できているとは言えない」と書いている。
一方でラウンド2相当の追試は、1回目に**本物を 3/3 で負けさせ**、
3体が同じ欠陥（すでに出た2つのエラーを章末でもう一度表にして説明し直していた）を
場所つきで指し、表を消したら2回目で判定が反転した（§8 追試の表）。
**FAIL を出した実績があるのはラウンド2の形だけ**である。

ラウンド2で抜く要素を「価値: 高の詰まりの記述」に固定する理由は、
選び方をその場の裁量にしないため。10:352 は
「『教材に載せる価値: 高』の詰まりは、その章の対話に必ず登場させる」と決めているので、
この要素は原則としてどの章にも存在し、かつ本物にしか無い。
§8 の追試が抜いたのもこれである。抜く要素を毎回書き手が選べる形にすると、
自分が勝てる要素を選べてしまう。

### [D17-3] 対照版を弱くして合格させることを禁じる

ラウンド2で本物が過半数を取れなかった場合の処置は、指された箇所の**本物側**の修正に限る。
対照版から要素をさらに抜く・対照版の文章を劣化させる方向の変更で合格させてはならない。

本物側の直し方には順序を課す。**重複の除去・配置の変更を先に試し、
教える内容そのものを消す変更は G6 exec の結果が出るまで行わない。**

**理由**: §8 が実際にやったのがこの順序である。1回目の FAIL に対して
「詰まりの記述を消す」ではなく「章末の再掲表だけを消して、詰まりの記述は
出てくる場所へ埋め込む」を選び、それで判定が反転した。
§8 は削るのをやめた理由も明記している —
この設問が測っているのは**読む前の好み**であって、
実際にディスクが埋まって手が止まった読者が同じことを言うかは実走でしか分からない。
「好みの投票だけで教える内容を削らない」。この線引きを手順に固定しないと、
FAIL のたびに教える内容が削られ、G6 read が教材を痩せさせる装置になる。

### [D17-4] 対照版の置き場は `g6/<章ID>/`。curriculum/ の外に置く

`g6/<章ID>/plain.md` と `g6/<章ID>/minus.md`。git 追跡する。

**理由**: D1-2 は `curriculum/` 直下を章ファイルだけの平置きと決め、
D1-8-2 は「直下の .md 集合が章分割表の章ID集合と一致しない」ことを
配線検査の FAIL 条件にした。対照版を直下に置くとこの検査が壊れる。
`curriculum/extra/` に置くことはできるが、そこは目次・付録・パート扉という
**読者に届く本文**の置き場であり、対照版は読者に届けてはいけない検査材料である。
配布物の分岐は既に3系統あり（棚卸し §4）、棚卸し:130 が自ら
「分岐が増えるぶん、前作より危険度は高い」と書いている。
前作#1（販売ZIPに完成品混入）の直系の経路を1つ増やす理由が無い。
`curriculum/` の外に置くと `material-writing-gate.sh` の
PreToolUse による文体スペック読み込み強制は掛からなくなるが、
D17-1 で G3 の文体チェックを課したので、書いた結果の検査は残る。

### [D17-5] 改訂タグを打った章は対照版も同じPRで更新する。同期は受領証で機械検査する（案。実装しない）

10 §4 の改訂手順（改訂タグ `chapter/<章ID>-r<K>` を打ってから G3〜G6 を再実行する経路）に
「対照版2本も同じPRで更新する」を加える。

同期の検査方法は、対照版の更新有無を差分の目視で見る形にしない。
**G6 read の受領証（G6RUN行）に、本物・`plain.md`・`minus.md` の内容ハッシュを記録し、
次回以降の RUN で本物のハッシュが変わったのに対照版のハッシュが変わっていなければ FAIL** とする。

**理由**: 対照版が古いまま G6 read を回すと、比較の対象が本物と別内容の文書になり、
勝敗が「改訂で良くなったか」ではなく「改訂したか」で決まる。
検査の合図を差分の中（コミットメッセージ・ファイル名・注釈）に置かない理由は
道具検証の記録 追記5 の結論と同じ —
「入力の中から合図を探す形は、その入力が任意の文字列を含みうる限り必ず抜けられる。
**合図は入力の外に置く**」。ハッシュは前回の受領証に置かれた、入力の外の合図である。
実装は Phase 2 のゲート実装で行う。ここでは様式だけを決める。

### [D17-6] 対照版の作成・更新を 07 の見積もりに別立てで置く。数字は入れない

07 §3 の「前作 task-app にはなかった要素」の一覧と、07 §4 のローリング見積の内訳に
**「G6 対照版2本の作成と、改訂時の更新」**を独立の行として置く。
**工数の値は空欄のまま置き、本番1章目の実施時に実測して埋める。**

**理由**: 現在 07・13・14 に対照版という語が一度も現れない（`grep -rn "対照版" material/*.md`
のヒットは 10:306 と 10:314 の2件のみ）。10:314 は
「本文から対話を抜いて箇条書きに直すだけなので、執筆時に短時間で作れる」と書くが、
これは D17-2 で2本立てになる前の見立てであり、しかも「短時間」の実測値は無い。
数字を今書かない理由は 15:118 と同じ —
根拠のない数字を置くと以降の全工程がその数字を前提に組まれる。
場所だけ用意して値を空にするのは D1-6 の「節目」列と同じ扱いにした。

## 2. D7 の決定

### [D7-1] パート完了 = 章分割表でそのパートに属する全章（tombstone 済みを除く）の状態が「マージ済み」になった時点

これが 14:128 と 10:273 の「G6RUN受領証が**各パート完了時**+月1を網羅」の発火時点である。
発火した G6RUN の対象範囲欄（10:262-264）には、そのパート名を書く。

**理由**: 監査 D7 は「そのパートの最終章の教材PRがマージされた時点」で足りるとしているが、
「最終章」は並び順に依存する。10:122-126 は伴走中の章の境界・順序の微調整を
ADR 1本＋局長の1行承認で認めており、D1-2 はファイル名から順序を外して
並び替えが起きる前提を明文化している。並び順に依存する定義を置くと、
微調整のたびに「どの章が最終章だったか」が動く。
全章がマージ済みであることは並び順に依存せず、章分割表の状態列（D1-6）だけで判定できる。
章は依存順の直列で進む（07:68-72）ので、実際に発火する時点は
「最終章のマージ時」と同じになる。定義だけを順序非依存にした。

### [D7-2] 完了したパートに章が追加されたら、そのパートの完了は取り消される

10:122-126 の軽量改訂手続きで、完了済みのパートへ章が追加された場合、
そのパートの完了は取り消され、追加章のマージ後にもう一度 G6RUN を回す。
先に取った G6RUN 受領証は履歴として残すが、Phase 3 完了条件の
「各パート完了時を網羅」の充足には使わない。

**理由**: 受領証は「走った証明」であって「通った証明」ではない（10:269-270）。
章が1本増えたパートに対して、増える前の実走の受領証で完了を主張できる形にすると、
受領証が「走らせずに完了条件を満たす」ための紙になる。前作#10 と同型。

### [D7-3]（系）パート進入 = そのパートに属するいずれかの章の実装PR（実装変更が無い章はN/A証跡）が最初にマージされた時点

07:68-72 のローリング見積は「各パートへ**進入**して序盤1〜2章の実測が出るたびに」更新する形で、
完了ではなく進入を単位にしている。完了だけを定義して進入を定義しないと、
同じ曖昧さが見積もり側に残る。定義の形は D7-1 と揃え、並び順に依存させない。

## 3. 決められなかったもの

- **[U17-1] 対照版2本の作成・更新にかかる工数と、G6 read 2ラウンドの実行コスト。**
  実測が要る。現物の対照版は捨て試作の2本しか無く、そのどちらも
  「作るのにどれだけ掛かったか」が記録されていない（道具検証の記録 §13 の約28分は
  2章目を1本通しで作った時間で、対照版の作成時間を切り出していない）。
  `g6-run.sh` は既定で実行体4体、閾値ちょうどならもう1周回すので、
  2ラウンドにすると最大で16体ぶんの実走になる。測り方: 本番1章目の G6 実施時に、
  (a) `plain.md` と `minus.md` の作成に掛かった時間を別々に記録、
  (b) 各ラウンドの実行体数・所要時間・再走の有無を G6RUN 受領証に記録、
  (c) ラウンド2で FAIL して修正・再測定した回数を記録。
  期限: 本番1章目の教材PRマージ前（この値が出るまで 07 §4 の対照版の行は空欄のまま）。

- **[U17-2] D17-1 の実測をルートの `.textlintrc.json` で取り直すこと。**
  実測が要る。§0.3 の値は、ルートと同じ規則集合を prototype-chapter の依存で
  再現して測ったものであって、ルート設定そのもので測った値ではない。
  ルート設定は依存が未導入で `No rules found` を返す（10:127 の既知の未了・B2 と連動）。
  測り方: 依存導入後にルートの `.textlintrc.json` で対照版2本を掛け、
  終了コードと指摘件数を記録する。あわせて §0.2 と同じ陽性テストを同設定で通し、
  検出器が生きていることを確認する（陰性だけでは何も言えない）。
  期限: D19（本番教材へゲートを掛け直す作業）の完了前。

- **[U17-3] ラウンド2で本物が負け続ける章が出たときの上限回数。**
  他の決定待ち。G4 は「FAIL→修正は2回まで、3回目もFAILなら局長エスカレーション」
  （10:212-213）と決めているが、G6 read に同じ上限を置くと、
  D17-3 が禁じた「教える内容を削って勝ちにいく」圧力がそこで最大になる。
  上限を置くかどうかは U17-1 の実測（1回の測り直しにどれだけ掛かるか）と、
  D18（G6 実走の完走）の結果を見てからでないと決められない。
  期限: 本番の最初の節目の章に入る前。

- **[U17-4] 対照版を「本物にしか無い要素」で作れない章の扱い。**
  他の決定待ち（D5・B1 の章分割の確定待ち）。開発ログが `ai-artifact` だけで
  構成される章は 10:349 で G3 警告の対象になっており、そういう章は
  ラウンド2で抜く要素を持たない。D17-2 は N/A 記録で通す形にしたが、
  N/A の章が何割になるかは章分割表が確定しないと分からない。
  半分を超えるならラウンド2は事実上機能していないことになるので、
  抜く要素の定義から見直す必要がある。
  期限: G1（章分割の凍結）の後、本番1章目の G6 実施前。

## 4. 見つけた矛盾（決め直していない。報告のみ）

1. **`g3-style.sh:18-20` の除外理由が事実と合っていない。**
   「わざと手順書調に書いてあるので文体ゲートに掛けても意味がない（掛けると必ず落ちる）」
