## 章表の書式を一つにする

正本は `material/18-chapter-split-table.md` のみ。別のJSON/YAML正本を作らない。
共通処理は `scripts/curriculum-qa/chapter_table.py`。他の検査はここをimportする。

- `版: <版識別子>` を文書に1回書く。現行下書きは `v35-draft-1`。
- `位置づけ: DRAFT / NON-G1` を1回書く。今回の検査入口は下書き専用であり、
  凍結表を受理する入口や正式ゲートへつなぐ処理は別途作る。
- `## 章一覧` にD1の9列、D5の3列、追加の `未決依存` 列をこの順で置く。
  未決依存は16のB/C IDのカンマ区切り、なしは `-`。CLIは16からID実在も照合する。
  import時の `validate_chapter_table` は既知ID集合を第3引数で受け取る（省略時は書式のみ）。
  `read_chapter_table` は16を必ず読む。見える変化はD5どおり `screen` / `tool`。
- `## 対応表` は `章ID / FR / 画面 / SQL/RLS / テスト / 前提知識 / 証拠` の7列。
  現役章ごとに1行。FRはFR1〜FR15のカンマ区切り、機能実装に対応しなければ `-`。
  対象外の画面等は単なる空欄ではなく理由を記す。証拠はリポジトリ内の非空ファイルの相対パス列。
  未取得は `-`。存在確認だけで実測内容の正しさを証明したとはみなさない。
- 各表の節には表だけを置く。説明は別の見出しへ分ける。セル内の `|` は使わない。
  コードフェンス内の例は実データではない。HTMLコメント、閉じ忘れフェンス、余分な表・壊れた列は拒否する。
- `節目` の未指定はC8待ちとして空欄を許す。指定値は `節目` / `非節目`。
  `supersedes` と前提がない場合は `-`。最初の結果は予定する節名を書き、未実測と明示する。
- ID規則はD1のまま。tombstoneも含め一意で再利用禁止。現役の順序は並び順の整数だけを読む。
  前提は現役かつ先行章のみ。tombstoneは現役の順序・依存グラフから外し、古い証拠は履歴のみに残す。
  現在のFR対応・証拠の行が廃止章や存在しない章を指したらFAIL。置換先の自動推測はしない。

`supersedes` に対応がある場合の書式もここで限定する。新しい現役章側に
`split:旧ID`（同じ廃止元から2章以上）、`merge:旧ID,旧ID`（2つ以上の廃止元）、
`rename:旧ID`（元IDはD1-4に従い表から置換済み）のいずれかを書く。
split/mergeの元IDは表内にtombstoneとして保持し、renameの元IDは他の行や別操作に再利用できない。
単純廃止はtombstone行を保持して `supersedes=-`、廃止元から新章への対応は後継側だけに置く。
後継章が後に廃止された場合は、そのsupersedes履歴も消さずに残す。履歴の循環は拒否する。
操作を行える時期（D1の未着手条件）と、その後の履歴維持を分ける。実装済みに進んでも履歴は残す。
操作時点の未着手・必要ADRの確認は履歴レビューの責務であり、この構造検査は過去状態を推測しない。
これらの書式に外れる任意文字列はFAIL。今回の章表には分割・改名操作を含めていない。

### 出力と終了コード

- `draftStructureValid`: 全パートの章表と対応表、ID、順序、依存、全FR網羅、例外参照の構造が有効。
- `unresolvedDependencies`: 現役章に明示された未決IDの集合。台帳全体の網羅を意味しない。
- `declaredGateInputsComplete`: 構造有効で、明示した未決・節目未指定・証拠未指定がない。
  台帳の取りこぼし、実測内容、承認の来歴・真正性、G0/G1充足を保証しない。
- 追加出力は現役章数、FR集合、現役章データ、エラー、未充足宣言。
- CLIは構造有効ならexit 0、不正なら1、入力を読めなければ2。正しい未決付き下書きはexit 0でも
  `declaredGateInputsComplete=false`。正式ゲートへCLIを接続する変更は今回含めない。

### tool連続例外の参照確認

3章以上連続するtoolは、既存G1の例外手続きを維持する。例外がある場合だけ
`## tool連続例外` に `対象章 / ADR / 承認記録` の3列表を追加する。
対象章は連続範囲全体のIDを順番どおりカンマ区切りにする。部分一致や余分な例外は拒否する。

参照するADRと別の承認記録には、次の項目を各1回記す。

```text
版: <章表の版>
対象章: <対象の現役章ID列>
ゲート: G1
種別: tool連続例外
範囲: sns-app/material/18-chapter-split-table.md
```

承認記録にはさらに `判断: 承認`、`承認者: 局長`、`ADR: <相対パス>` を記す。
この書式は新規記録の突合用であり、文字を記入するだけで承認を取得できる仕組みではない。
独立レビューが実際のユーザー発言・記録の来歴と対象を確かめる。今回、例外も承認も新設していない。
参照パスはリポジトリ外・絶対パス・空ファイル・解決先が外部のsymlinkを拒否する。
