## 6. sns-app の push で動く workflow とデプロイ連携先

読み取りだけで調べた（`.github/workflows/*.yml`、`renovate.json`、`.coderabbit.yaml`、追跡ファイル）。

| workflow | 起動条件 | 外部への書き込み |
|---|---|---|
| `gates.yml` | `push` は main だけ。`pull_request`（opened / synchronize / reopened / ready_for_review / converted_to_draft）。draft の PR では job が skip（`:51`） | 無し（`permissions: contents: read`、`:45-46`） |
| `trufflehog.yml` | `push` は main だけ。`pull_request`（draft でも走る） | 走査だけ |
| `merge-quality-gate.yml` | main 向け PR の closed | Slack へ投稿（`SLACK_BOT_TOKEN`、`:78,135`） |
| `ci-failure-notify.yml` | 上の3本の `workflow_run` 完了。branches は main / develop | Slack へ投稿（`:21,78`） |
| `devin-slack-trigger.yml` | issue に `devin` / `devin-queued` ラベル | Slack 投稿と issue 書き込み（`issues: write`） |
| `devin-slack-retry.yml` | cron（6時間ごと）と手動 | 同上 |

- 作業ブランチ（main 以外）へ push しただけでは、どの workflow も起動しない。PR を作ると gates（draft なら skip）と trufflehog が走る。
- デプロイの連携先は、リポジトリ内には見つからなかった。`vercel.json`・`netlify.toml`・`eas.json`・`render.yaml`・`fly.toml` は追跡されていない。
  7つある `app.json` には EAS の `projectId` も `updates` も無い。workflow に `git push`・`EXPO_TOKEN`・`supabase db push` は無い。
- GitHub App 側の連携（CodeRabbit は `.coderabbit.yaml` があり PR をレビューする。Renovate は `renovate.json` で github-actions の minor/patch を自動マージする）は
  リポジトリの外の設定なので、どの App が実際に入っているかは確かめていない。
