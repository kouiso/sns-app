## 1. 実測でできたこと

### 1-1. 組版そのものは成立する

- 捨て試作の章（`prototype-chapter/chapter.md` ほか）をそのまま PDF 化できた。
  `vivliostyle build` は SUCCESS。7ページ / 341,548 bytes。
- **日本語は化けない。** `pdftotext -layout` で
  「阿部「投稿って、プログラムから見ると何なんですか」」「磯貝「箱です。…」」が
  そのまま抽出でき、100dpi の画像化でも約物・鉤括弧・全角括弧が正常に組まれた。
  PDF は Tagged: yes でテキスト選択・検索が効く。
- EPUB も同じソースから出る（出力先の拡張子を変えるだけ）。
  `mimetype` / `META-INF/container.xml` / `EPUB/*.xhtml` / `content.opf` の正しい構造。
  **EPUB は Chromium を起動しないので PDF より速い。**
- ページ下部脚注（`float: footnote`）・柱（`string-set` ＋ `@page` の
  `@top-center`）・ノンブル（`counter(page)`）は CSS 組版で全部動いた。
- 複数章を1冊に束ねるには `vivliostyle.config.js` の `entry` 配列が要る
  （複数ファイルの直接指定は `too many arguments` で不可、`entry` の省略は
  `Invalid key: Expected "entry" but received undefined` で exit 1）。
  `entry` を外部 JSON から生成する構成（`require('./chapters.json').map(...)`）は
  実測で動いた。
- 速度（50章スケール、`~/.cache/vivliostyle/browsers` が温まった状態）:
  PDF 34.8s / 353ページ / 1,611,558 bytes、EPUB+webpub 同時 6.9s。
  **CI に載せられる速度である。**

### 1-2. VFM 独自記法の可否（実測）

| 記法 | 結果 |
|---|---|
| ルビ `{東京都|とうきょうと}` | 動く（`<ruby>`＋`<rt>`）。**モノルビ分割 `{漢字|かん|じ}` は非対応**（rt が `かん\|じ` になる） |
| 見出しの属性 `## 見出し {.break-before}` | **動く**。`<h2 class="break-before" id="見出し">` になる（本書執筆時に再実測） |
| 段落の属性 `{.lead}` | **効かない**。`<p>段落に属性{.lead}</p>` としてそのまま紙面に印字される |
| コードフェンスのファイル名 ` ```ts:app/index.ts ` | 動く（`<figcaption>` になる） |
| 脚注 `[^label]` | 動くが**章末の後注**になる。ページ下部にしたいなら生 HTML ＋ CSS |
| 行内脚注 `[^ここが本文]` | **壊れる**。参照の `<sup>1</sup>` だけが出て脚注本文の実体が出力されない（リンク切れ） |
| 数式 `$E=mc^2$` / `$$…$$` | **組まれない**。MathJax を CDN から読む `<script async>` を吐くだけで、PDF ビルド時に実行されず `\(E = mc^2\)` が生のまま印字される |
| fenced div `:::note warn` / `[toc]` | 未対応。そのまま文字として印字される |
| 改ページ `<div class="pagebreak">` ＋ CSS | 動く |

### 1-3. 話者ラベル「磯貝）」形式（12 §1.1）は組版と噛み合う

- **ただし条件つき。** 話者行の間に空行を1つ置いた場合に限り、各発話が独立した
  `<p>` になる。**空行を省くと複数の話者が1つの `<p>` に合流する**
  （`<p>磯貝）行1です。\n阿部）行2です。</p>`）。`hardLineBreaks:true` にしても
  `<br>` が入るだけで1段落のままなので、段落単位の CSS は話者ごとに効かない。
- CSS だけで台本の体裁（ぶら下がりインデント）は作れる。実測した CSS は
  `section p { padding-left: 4.5em; text-indent: -4.5em; }`。PDF で目視確認済み。
- **出力 HTML に話者を示す要素もクラスも無い。** ラベルだけを太字にする・色を変える
  といった装飾は CSS 単独では不可能。装飾したければ生 HTML で包むことになるが、
  それは §2-2 の文体ゲートの穴を自分で開ける行為なので採らない。

## 2. できなかったこと（壊れ方の実測）

### 2-1. ★ G5（embedmd）と VFM が同じ1行の上で正面衝突する

**最も重い1件。**

- `embedmd` の引用指示は終端正規表現に `\)` を要求する。裸の `)` は Go の RE2 が
  受け付けない。本書執筆時の再実測:

  ```
  bare.work.md:3: could not extract content from listings/App.tsx:
    error parsing regexp: unexpected ): `^});`   → exit=2
  /^}\);/  → exit=0（正常展開）
  /^}.;/   → exit=0（正常展開）
  ```

- 一方 VFM は、指示行の括弧の中に `)` が1個でもあると（**エスケープしても**）
  その行をリンク参照定義として解釈できない。本書執筆時の再実測
  （`@vivliostyle/vfm` 2.7.2 の `VFM({partial:true})`）:

  ```html
  <p>
    [embedmd]:# (listings/App.tsx tsx /^const styles/ /^});/)
    <code>tsx const styles = StyleSheet.create({ a: 1, });</code>
  </p>
  ```

  **指示行が本文として印字され、直後のコードブロックが段落へ吸収されて消える。**
  `/^}.;/` に書き換えると `<pre class="language-tsx">` が正しく出る（同じく再実測）。

- これは仮想の例ではない。`prototype-chapter/chapter-expo-first-screen.md:82` が
  現に `/^}\);/` であり、実際に組んだ PDF の11ページ目で StyleSheet のコードが
  1本の走り書き段落に化けた。
- **`});` で閉じる形は React Native / Expo / Supabase のコードで支配的**である
  （`StyleSheet.create({…})`、`useEffect(…)`、`createClient(…)`）。稀な形ではない。
- **このとき全ゲートが緑のまま教材が壊れる。**
  `embedmd -d` exit=0 ／ `tools/g5-quote.sh` は「G5 PASS」exit=0 ／
  `textlint` exit=0 ／ `vivliostyle build` exit=0。

**採れない回避策**: 「`/^}\);/` を `/^});/` に書き換える」は embedmd 側が exit=2 で
落ちるため**物理的に成立しない**。この案は採用しない。

**実測で成立する手は3つだけ**:
1. 終端正規表現を `)` を含まない形にする（`/^}.;/` は両側で通ることを実測。
   ただし `.` が何を指すか本文からは読めない）
2. 組版用の派生 md を作る際に指示行を落とす
   （`sed -E '/^\[embedmd\]:# *\(/d'` で PDF から `embedmd` の文字列が0件になることを実測）
3. 終端アンカーを `);` を含まない別の行に置く

どれを採るにせよ、**書いた瞬間に落とす検査**（引用指示の括弧内に `)` を含む行を FAIL）
と併用しないと、書き手は壊したことに気づけない。

### 2-2. ★ G3（textlint）が一度も見ない場所に「本に印刷される日本語」ができる

VFM を採用すると、以下は textlint の検査対象外なのに紙面へ出る:

| 場所 | 紙面での現れ方 |
|---|---|
| frontmatter の `title` | `<title>` → PDF の目次・しおり |
| 画像の `alt` | VFM が `<figcaption aria-hidden="true">` に複製して本文として見せる |
| コードフェンスの `:ファイル名` | `<figcaption>` になる |
| ブロックレベルの生 HTML（`<div>` / `<aside>`） | 中身がそのまま本文として組まれる |

実測（本書執筆時に再確認）:

```
$ printf -- '---\ntitle: ついに始まる魔法のような章\n---\n\n本文です。\n' > /tmp/t5.md
$ ./node_modules/.bin/textlint -f compact /tmp/t5.md ; echo EXIT=$?
EXIT=0
```

同じ文字列を本文に置くと prh が3件（「ついに」「魔法」「日です！」）検出して exit=1 になる。
frontmatter 付きのファイルを組版すると、PDF の目次に
「1. ついに魔法のような画面が出る日です！」が印刷された。

禁止表現6件を含む章が textlint EXIT=0 で通ることを別途1本の md で確認している。
これは 10:33（前作#10「AIの100%合格虚偽報告」対策）と同じ失敗を**ゲート自身がやる**形になる。

**なお、インラインの生 HTML（`<span>` の中）は textlint が検査する**（実測）。
ページ下部脚注を `<span class="fn">` で書いても G3 の穴にはならない。

### 2-3. ★ ルビ記法が prh の禁止表現辞書を無効化する

本書執筆時の再実測:

```
$ printf '# t\n\n型は便利だと言えるでしょう。\n\n型は便利だと{言|い}えるでしょう。\n' > /tmp/t4.md
$ ./node_modules/.bin/textlint -f compact /tmp/t4.md
/tmp/t4.md: line 3, col 6, Error - と言えるでしょう => です (prh)
1 problem   EXIT=1
```

**3行目（ルビなし）は検出、5行目（`{言|い}` 入り）は無検出。**
`prototype-chapter/prh/sns-app.yml:143` の
`/と言えるでしょう|と言えます|ではないでしょうか/` がルビ記法で分断されて素通りする。
57ルールのうち、漢字を含み複数文字にまたがるパターンはすべて同じ穴を持つ。

加えて `sentence-length: max 100`（`.textlintrc.json:3-4`）は**レンダリング後ではなく
Markdown ソースの文字数を数える**。読者が見る96字の文が `sentence length(102)` で
FAIL した（実測）。ルビ1個につき波括弧2字＋パイプ1字＋読みの字数が余計に乗る。

### 2-4. `vivliostyle build` の exit code は組版の破綻を検知しない

| 入力 | ログ | exit |
|---|---|---|
| 長いコード行（版面外へはみ出す） | 何も出ない | **0** |
| 存在しない画像の参照 | `ERROR 404 http://localhost:13000/…/nonexistent.png` | **0** |
| `\)` 入りの embedmd 指示（本文流出） | 何も出ない | **0** |
| 未展開の md（コードが丸ごと消える） | 何も出ない | **0** |
| config 不正 / entry のファイル欠落 | エラー | 1 |

**落ちるのは config 不正と entry ファイル欠落だけ。**
「機械ゲートは exit code で合否」（10:243-248）をそのまま適用すると、
組版の破綻が全部すり抜ける。

### 2-5. 長いコード行が無音で切り落とされる

既定（theme 未指定・A5）では長い行が版面の外へ出て**切り落とされる**。
`return { id: crypto.randomUUID(), body, createdAt: new Date() };` が PDF 上では
`… createdAt:` で終わり、`new Date() };` が消えた。
`grep -c AsyncStorage` が **0** になる例も別途確認している。ビルドは SUCCESS。

CSS（`pre { white-space: pre-wrap; word-break: break-all; }`）を当てれば全文が残る。
ただし継続記号は付かず、`break-all` なので識別子の途中でも割れる
（`VeryLongN` / `ame`）。**教材コードの折り返し規則は自前で決める必要がある。**

判型・本文級数を決めていないので、「何桁で切れるか」の確定値は無い
（A5・既定書体での観測値は半角50〜74桁前後・全角44桁前後とばらついた）。

### 2-6. 相対リンクが組版時の localhost に焼き付く

`pdftohtml -stdout -i -noframes` でリンクを列挙すると:

```
href="https://github.com/kouiso/sns-app"                      ← 絶対 URL は生きる
href="http://localhost:13000/vivliostyle/appendix.md"          ← 死ぬ
href="http://localhost:13000/vivliostyle/snapshots/ch02.zip"   ← 死ぬ
```

読者の手元では確実に死ぬ。`pdftotext` にはリンク文字列しか出ないので
**テキスト抽出だけの検査では見つからない。**

### 2-7. 作業ディレクトリのファイルが配布物へ混入する

作業用に置いた PNG が EPUB へ全部同梱された（15 files 中6件）。
webpub でも `listings/*/assets/` の画像が丸ごとコピーされた（1.1MB）。
`.md` や `.ts/.tsx` は入らない。**配布物のビルドは清潔な専用ディレクトリで行う前提が要る。**

### 2-8. PDF は原稿の構造を失う（既存の文字列検査が空振りする）

- インラインコードのバッククォートが消え、`` `src/` `` が裸の `src/` になる
- 行の折り返しで文が分断され、`grep '折り返しを起こしてみます'` が0件になる
- 既定の `pdftotext` はコードブロックの先頭インデントを落とす（`-layout` を付けると残る）

**28本＋G3/G5 を PDF に当てるという発想は成立しない。** 検査の層を分ける必要がある。

一方 **EPUB は ZIP + XHTML で原稿の構造を保つ**（`<code>` / `<pre class="language-tsx">` /
相対 `href` がそのまま残る）。パッケージのエントリ名と本文参照を照合する型の検査は
EPUB に対してならほぼそのまま移植できる。

### 2-9. CSS の入口

- `-s` は `--style` ではなく **`--size`**。`-s wrap.css` を渡してもビルドは exit 0 で
  SUCCESS し、CSS は一切当たらない（無指定と同一バイト数の PDF が出る）
- `--user-style "file://$PWD/wrap.css"` は build 出力に効かなかった
- `--style wrap.css` は**効く**（`grep -c AsyncStorage` が 0 → 1 に変わった）。
  ただし**コンテキストディレクトリ配下**にしか置けない（`../wrap.css` は ERROR）
- `vivliostyle.config.js` の `theme:` も効く

**入口が2つある。**どちらを使うかを固定しないと「CSS を当てたつもりで当たっていない緑」が
普通に起きる。

## 3. 既存ゲートとの共存は成立するか

### 3-1. G5（引用ゲート）は据え置き

**G5 の決定内容（10:284-322）は変えない。**
(1) 引用方式（教材が `listings/` から embedmd で引用する）、
(2) 合否は `embedmd -d` の終了コード、
(3) 引用範囲の妥当性は保証せず G4 で見る — この3点はどれも今回の問題の原因ではない。
実測でも `embedmd -d` は正しく展開し、md としては正しい。

壊れるのは**まだ工程に存在しない組版段階**である。必要なのは:

1. 10 §4 に**組版工程を1段追加**し、順序（`embedmd 展開` → `vivliostyle build`）と
   「逆順は無音で壊れる」ことを書く
2. 10:310-316「この方式が保証しないこと」に**1項目追記**
   （組版した成果物が壊れていないことは G5 では分からない）
3. **執筆規約**（引用指示の括弧内に `)` を書かない）
4. **組版後検査**（PDF テキストに `embedmd` が0件）

引用方式そのものの再決定は提案しない。

### 3-2. G3（文体ゲート）は穴が3つ開く

| 穴 | 中身 | 起票先 |
|---|---|---|
| 検査対象外の本文 | frontmatter / 画像 alt / コードフェンスのファイル名 / ブロック生 HTML | B54 |
| 禁止表現の素通り | ルビ記法が prh のパターンを分断する | B55 |
| 偽 FAIL | `sentence-length` がソース文字数を数える | B55 |

**textlint そのものは VFM 記法で誤爆しない。** VFM 記法（ルビ・脚注参照・脚注定義・
行内脚注・改ページ div・数式・コードフェンスのファイル名・画像属性・強調属性）を
入れた陰性サンプルは指摘0件・EXIT=0、陽性サンプルは 70/70 検出で、いずれも
VFM 記法を入れない元のサンプルと同判定だった。
ルビの親文字側・読み側・脚注定義の中・行内脚注の中・数式の中に入れた禁止表現も
prh が拾っている。**壊れるのは §2-3 の「ルビが1つの語をまたいで分断する」場合だけ**である。

`scripts/curriculum-qa/check_tone.py` も VFM 記法入りで同判定だった
（陰性 EXIT=0 / 陽性 EXIT=1・22件検出）。行ベースの正規表現なので影響を受けない。

### 3-3. 順序は一方向にしか成立しない

```
listings/<章ID>/ → embedmd 展開 → vivliostyle build → PDF / EPUB
```

逆順（未展開の md を Vivliostyle に渡す）は**警告もエラーも出さずに SUCCESS を返し、
コードだけが消えた PDF を作る**。工程の順序を間違えたことが成果物からしか分からない。

なお `tools/g5-quote.sh` は「引用指示が1本も無い章」を exit 2 で落とす検査を持つため、
指示行を落とした派生 md に当てると必ず落ちる（実測）。
**G5 の対象は必ず正本 md に固定する。**既定グロブは `$ROOT/chapter*.md`（非再帰）なので
派生物を `build/` 配下に置く限り誤検知しない。

## 4. 配布形式（B9）はどう決まるか

### 4-1. 決まったこと

- Vivliostyle が出せるのは **PDF / EPUB / webpub（静的 HTML 一式）** の3系統だけ。
- C6 で **ZIP 配布は採らない**、**サイト構築は不要**が局長回答済み。
  よって webpub は落ち、残るのは PDF と EPUB。
- 両方作るコストは**出力先を変えたビルド1回分**でしかない（実測）。
- PDF のみ Chromium 依存で遅い（50章 34.8s）。EPUB は Chromium 不要（6.9s）。
- **EPUB は原稿の構造を保ち、PDF は失う**（§2-8）。

→ **B9 は「教材本文＝PDF を正本、EPUB を機械検査用に併産」で決着させた**（16 B9 決定節）。
EPUB を読者に配るかは C6 の配布経路の運用に属するので本書では決めない。

### 4-2. 決まらないこと（局長判断）

**章末スナップショット（A7）の置き場**が決まっていない。
公開リポジトリの成果物にするか Drive に置くかで、配布系統の数も検査対象も変わる。
**PDF 本文からスナップショットへリンクを張るには宛先の絶対 URL が要る**（§2-6）。
これは公開範囲と配布経路そのものなので、受注側が選択肢を絞って決める事項ではない。
→ 16 C7 として起票した。

### 4-3. 系統数の食い違いを直した

16 B9 は「本体＋章末スナップショットの**2系統**」と書いていたが、
C3 で完成コードが公開リポジトリに出ることが確定しており、
`decisions/task-app資産棚卸し.md` は「本作は配布が**3系統**」と書いている。
B9 の行だけが2系統のままだった。**3系統**（教材本文＝PDF ／ 完成コード＝公開リポジトリ ／
章末スナップショット）へ訂正した。

### 4-4. 配布形式の語彙は複数箇所で同時に変わる
