## 1. [D15-1] 記録先は `material/reviews/g4/<章ID>.md`。1章1ファイル

- 受領証の置き場: `material/reviews/g4/<章ID>.md`
- ファイル名の `<章ID>` は D1-3 の規約（`^[a-z][a-z0-9]*(-[a-z0-9]+)*$`・3〜32文字・
  末尾セグメントが純粋な数字のものは禁止・章分割表で一意）に従う。受領証の側で新しい
  名前を作らない
- ラウンド（初回＋修正2回）は**同じファイルに追記**する。ラウンドごとにファイルを
  分けない
- テンプレートは `material/reviews/_template_G4受領証.md`（`g4/` の外・`_` 始まり）
- 既存の `material/reviews/codex-round*.md`（設計文書レビュー）はそのまま `reviews/`
  直下に残す。章の G4 と混ぜない

理由:

1. `material/` に置くのは、受領証が教材本文ではなく制作側の記録だから。
   `curriculum/` 配下には置けない（D1-1・D1-7 と同じ理由で、あそこは文体ゲートの
   deny 対象であり、受領証はレビュアの原文をそのまま貼る文書なので 12 の文体規則を
   当てる対象ではない）。`dev-logs/` にも置かない（D1-7 は開発ログを1章1ファイルと
   定めており、そこへ別種の記録を混ぜると `test -f dev-logs/<章ID>.md` の存在確認
   〔10:201〕が「開発ログがある」を意味しなくなる）
2. `reviews/` の下に `g4/` を切るのは、既存13本と混ざると「章の G4 が全章ぶん揃って
   いるか」を数えられなくなるため。`g4/` 直下の `.md` 集合と章分割表の章ID集合を
   突き合わせる形にすると、D1-8-2 の配線検査（`scripts/check-gate-wiring.sh`）が
   listings・snapshots・dev-logs と同じやり方で受領証も見られる
3. 1章1ファイルにする理由は、修正回数のカウンタ（§4）を1箇所に置くため。
   ラウンドごとにファイルを分けると、回数を数えるのに glob とファイル名の解析が要り、
   `-r2` のようなサフィックスが改訂タグ `chapter/<章ID>-r<K>`（10:320）と同じ字面に
   なって、どちらの意味かがファイル名から判別できなくなる
4. 章IDを使うのは、同じ文字列が `chapter/<章ID>` タグ・`curriculum/<章ID>.md`・
   `listings/<章ID>/`・`snapshots/<章ID>/`・`dev-logs/<章ID>.md` の5実体に既になって
   おり（D1-2）、受領証を6実体目として同じ grep で辿れる形にするため

**本決定と同じPRでやること**: `material/reviews/g4/README.md` を置いてディレクトリを
実在させる。理由は D1-1 と同じで、ディレクトリの不在が「まだ1章も G4 を通していない
正常な状態」なのか「置き場所を間違えている」のかを、検査の側から区別できないため。

## 3. [D15-3] 合否を数える観点は3つ。退屈度は記録欄に降ろす

**この点は D0 が既に決めている**（`material/decisions/D0_台帳の記述ズレ修正.md` §1-4:
「合否観点は3つ（技術正確性 / 完成品へのつながり / 文体逸脱）、退屈だった箇所は G4 でも
聞いて記録するが合否には数えない」）。本書はそれを決め直さず、様式の側で実装する。

矛盾の中身（10 の現物、2026-08-06 時点で未修正）:

- `10:208-209` 観点は固定4つ（技術正確性 / 完成品へのつながり / **退屈度** / 文体逸脱）で
  観点別PASS/FAILを記録し、全観点PASS=合格
- `10:210-211` 「退屈度」の判定方法は G6 の比較評価に一本化する。レビュアーの主観コメントを
  退屈度の合否根拠にしない
- `10:205-206` レビュー観点に「完成品へのつながりが見えるか・**退屈でないか**」を必須で
  含める（11:97 由来）

3文を全部立てるには「聞く観点」と「合否を数える観点」を分けるしかない。よって:

1. 受領証の §3 は3行の表（技術正確性 / 完成品へのつながり / 文体逸脱）。全 PASS で合格
2. 退屈だった箇所は §5 の記録欄で聞く。**PASS/FAIL を付けない**。10:205 の「必須で含める」は
   この記録欄で満たす
3. §5 の記入内容は、その章の G6 比較評価の設問2（10:312「本物を読んでいて退屈だった箇所」）へ
   持ち越す。書き直し対象を決めるのは G6 側

捨て試作の実測もこの形になっている（`prototype-chapter/道具検証の記録.md`:259-260
「観点3つ（技術正確性 / 完成品へのつながり / 文体逸脱）で採点させた。退屈度は §8 の
比較評価へ移したのでレビュー観点から外した」）。様式が実測と食い違わないほうを採る。

10 本体の書き換えは D0 の shared_edits が持っているので、本書からは重複して出さない
（§8 の起票を見よ）。

## 4. [D15-4] 修正回数のカウンタは「同一の対象タグ内のラウンド数」

- ラウンドは R1（初回）・R2（修正1回目）・R3（修正2回目）。**R3 が FAIL なら局長
  エスカレーション**（10:211-212）
- カウンタの単位は**対象タグ**。R1〜R3 は同じ `chapter/<章ID>` に対する連番
- 実装側欠陥が原因で修正実装PRがマージされ、改訂タグ `chapter/<章ID>-r<K>` が
  打たれた場合（10:318-322）、そのタグに対して R1 から数え直す
- 教材PRマージ後の改訂（乖離分類(b)・(c)。10:274-283）で G4 を回す場合も、その時点の
  最新タグを対象タグとして R1 から数える
- カウンタは受領証の「ラウンド一覧」表の行数で数える。別の場所に持たない

理由: 10:211-212 は回数の上限だけを決めていて、何を1回と数えるかを書いていない。
「章ごとの通算」で数えると、実装側の欠陥（10:318-322 は教材の修正ノードへ戻さないと
明記している）や販売後の改訂で回したぶんまで上限を食い、教材側の問題が2回も直せない
まま局長へ上がる。逆に無制限にすると 10:211「無限ループ禁止」が効かない。
対象タグを単位にすると、教材側の修正で回した回数だけが数えられ、実装側の修正が入った
時点で状況が変わったことがタグの変化として記録に残る。

エスカレーション中は教材PRをマージしない（10:207「推敲上限に達しても合格しない場合は
自動保存せず局長へエスカレーション」＝前作#13 対策）。

## 5. [D15-5] 発注手順

### 誰が

発注するのは伴走フェーズのオーケストレーター（10:259 が RUN 受領証の実行責任者として
置いている人格と同じ）。判定するのは別ファミリーのAI。受領証に記入し、成立/反駁を
判断するのは受注側。

### 何を渡すか

| 渡す | 理由 |
|---|---|
| 教材ドラフト本文（**embedmd 展開後**の、読者が読む形） | 引用範囲の過不足（10:227-233）は展開後の本文でしか見えない。`[embedmd]:# (...)` の指示だけを渡すと、レビュアは引用の中身を読まずに判定する |
| `listings/<章ID>/` の全ファイル | 技術正確性と「引用に含まれていない必要行があるか」の判定に、引用元の全体が要る |
| 章分割表（`material/17_章分割表.md`）の当該行 | 「完成する状態」「前提とする前章成果」が無いと、完成品へのつながりを何と照らして判定するのかが決まらない（10:113-114） |
| `12_文体・AI臭さ排除方針.md` | 文体逸脱の判定基準。12 は G2 で凍結する声の定義の正本（10:129） |
| 前章までの章タイトル一覧 | 「前章からの接続」を見るために順序の文脈が要る |
| 前ラウンドの指摘と処置内容（R2 以降のみ） | 処置そのものの妥当性を別ファミリーに当てた前例がある（`material/reviews/codex-round13-14.md` 冒頭「その処置そのものが正しいかを、別ファミリーのAIに当てた回である」） |

### 何を渡してはいけないか

| 渡さない | 理由 |
|---|---|
| `dev-logs/<章ID>.md`（開発ログ） | 開発ログはエラーの全文と解決手順を持つ（10:338-345）。これを見たレビュアは、教材から手順が抜けていてもログで補完して「分かる」と判定する。16 A5-3 が G6 について「教材外の知識で補完して進んだ箇所はそれ自体を欠落として記録する」と決めているのと同じ穴を、G4 で開けることになる |
| 設計書（00〜16。12 を除く） | 上と同じ。設計書には教材が書いていない前提が全部載っている |
| 生成側のセッション文脈・生成プロンプト・推敲の途中版 | 16 A6 が「自分の生成物を同一ファミリーでレビューして合格にする経路は禁止」と決めており、生成意図を渡すことはその経路を文脈の側から再現する |
| 対照版（手順書調の比較用の版） | 退屈度は G6 の比較評価へ一本化されている（10:210）。対照版を渡すと G4 で実質の退屈度判定が起き、10:211「レビュアーの主観コメントを退屈度の合否根拠にしない」を迂回する |
| 他の章（束ねての発注） | Round 13 の実測。「G5 で章をまとめて渡すと、片方がズレ・片方が読めない時に出力が混ざり、読めない方が隠れて『ズレ』と報告される」（`material/reviews/codex-round13-14.md` #2）。Round 12 は範囲を絞らずに投げて文脈上限に当たり、結果が1件も出ないまま落ちている（`ran out of room`）。1発注1章にする |

### 何を受け取るか

1. 3観点それぞれの PASS/FAIL と、その根拠
2. §3.1 の3問への明示回答（「指摘なし」は回答として受け付けない）
3. 指摘一覧（重大度・箇所・内容）
4. 退屈だった箇所（無ければ「無し」）
5. 応答したモデルの識別子

受け取ったら受領証へ転記し、成立/反駁を受注側が判断する。
レビュアの出力を要約せずに済む欄（根拠列・指摘列）には原文を貼る。

## 6. [D15-6] ファミリーの記録と代替

- 生成側は Claude、レビュー側は別ファミリー（Codex/GPT系）、代替はさらに別系統
  （16 A6）。受領証の §1 に「指定か代替か」「代替を使った場合はその理由」を書く
- 代替を使った場合でも、生成側と同一ファミリーになってはいけない。§1 に生成側
  ファミリーを併記させているのはこの確認のため
- 「事前に1つ決めておく代替ファミリー」（10:212-213）の具体名は**本決定では決めない**。
  入手可能性の実測が要る（§9 U15-1）

## 7. [D15-7] 反駁の扱い

- 受注側は指摘に反駁してよい。前例がある（`material/reviews/codex-round13-14.md`
  Round 13 #2 は、指摘は成立するが前回の直し方が成立しないことを実測で示している）
- ただし**反駁を根拠に FAIL を PASS へ書き換えない**。FAIL の解除は次の2経路だけ:
  1. 処置して次ラウンドを発注し、レビュア側が PASS を返す
  2. 反駁の根拠（実測・公式資料・ファイル行）を受領証に書き、**反駁文ごと**次ラウンドの
     レビュアへ渡して再判定させる
- どちらもラウンドを1回消費する

理由: 受注側が自分で判定を書き換えられると、前作#10（AIの「100%合格」虚偽報告。10:28）が
そのまま再生産される。10:28 は G4 を「観点別PASS/FAILの構造化記録」で守ると書いており、
記録の形だけあって書き換えが自由なら守れていない。

## 8. [D15-8] 機械検査（案。本決定では実装しない）

D1-8-3 の共通規約（走査対象0件は FAIL、対象があっても検査件数0なら FAIL）に乗せる形で、
受領証そのものを検査する案を置く。実装の要否は B31 の分類結果しだい（§9 U15-2）。

1. `material/reviews/g4/` 直下の `.md` の basename が、章分割表の生きている章ID集合に
   含まれること（tombstone 済みIDの受領証が残っていたら FAIL）
2. 教材PRの対象章に受領証が存在すること（`test -f material/reviews/g4/<章ID>.md`）
3. 受領証に `<...>`・空セル・「未記入」が残っていないこと
4. 観点表が3行あり、3行とも PASS/FAIL のどちらかであること
5. §3.1 の3問すべてに回答があり、2問目・3問目が「有り」なら技術正確性が FAIL であること
6. 同一対象タグのラウンドが3を超えないこと、R3 が FAIL なら §7 の局長裁定欄が埋まって
   いること
7. 総合判定 PASS の受領証で、3観点のいずれかが FAIL になっていないこと
