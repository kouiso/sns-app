# 00. 企画概要

## 目的（何のためにこの教材を作るか）

インターンが「プログラミング言語を1つ覚えれば、Web もスマホアプリも自分で作れる」
という実感を持てるようにする。前作の `task-app`
（タスク管理アプリ＝Redmineモドキ、30日間ハンズオン）は Next.js による
Web単体のフルスタック学習だった。今回はその発展として、**同じ TypeScript を使い、
プラットフォームを横断して1つのサービスを配信する**体験を提供する。

**「サーバーを自分で作る」学習は、本教材ではなくシリーズ全体で満たす。**
本教材のバックエンドは Supabase（既製のサービス）を使い、サーバーフレームワークを
自分で書く学習は第3弾の NestJS 教材へ分離した（経緯は `02_技術選定書.md` §3、
位置づけは `09_教材シリーズロードマップ.md`）。1つの教材に道具を詰め込みすぎると
分量と難易度の両方が跳ね上がり、SNS を作る学習そのものが薄くなるため。

題材は SNS（Twitterモドキ）。理由:
- 認証・投稿・フィード・フォロー関係・通知・検索・画像アップロードなど、
  実務で頻出する技術要素をひと通り含む
- 「タイムライン」「いいね」「リプライ」など機能の意味が直感的で、
  初心者でも完成イメージを持ちやすい
- スマホの機能（カメラ）と、**RLS（Row Level Security ＝ 行レベルセキュリティ。
  「誰がどの行を読み書きできるか」を DB 自身に守らせる仕組み）** という、
  前作には無かった学習機会になる

## シリーズ内の位置づけ — 「TypeScript Everywhere」

本教材は単発ではなく、以下のシリーズの第1弾と位置づける
（シリーズ全体の詳細は `09_教材シリーズロードマップ.md` を参照）。

> 同じ TypeScript の知識で、Web・モバイル・デスクトップ・CLI・ブラウザ拡張まで
> 作れることを、実際に動くクローンアプリを通じて体感させるシリーズ。

第1弾である本教材では「1つの TypeScript コードベースを iOS / Android と Web の
両方に配信する」体験を軸に据える。手段は Expo（React Native）で、
**1章目から自分のスマホで動く**ところから始める（詳細は `02_技術選定書.md`）。

## 成功基準（この計画フェーズの完了条件）

計画フェーズ（本ドキュメント一式）が完了したと言えるのは、以下がすべて揃った時点:

1. `01_要件定義書.md` の機能要件・非機能要件・スコープ外に局長の承認が出ている
2. `02_技術選定書.md` の技術スタックが確定し、比較検討の理由が明文化されている
3. `03_基本設計書.md` のシステム構成図・画面一覧・ER図（概要）が確定している
4. `05_DB設計書.md` のテーブル定義が機能要件をカバーしている — ただし05 §4の既知の
   未解決6点は「Phase 1で解消する」ことを承認事項に含める（完全解消はPhase 1完了条件。
   Codex R3 MAJOR1対応で循環を解消）
5. `07_開発スケジュール.md` の工程が局長と合意されている

工程の順序・開始条件の**正本は `14_マスターロードマップ.md`**。本節と14が食い違う場合は14に従う（Codex R1 C1対応）。

上記5点は**Phase 0（計画固め）の完了条件**である。実装（コードを書くこと）の開始条件は
これではなく、`14_マスターロードマップ.md` のPhase 1・Phase 2の完了（正本 — Codex R2対応）。
前回までの反省（計画が甘いまま実装に入って手戻りが発生した失敗）を踏まえ、
今回はこのゲートを厳守する。

## この計画フェーズで「やらないこと」

- コードの実装（プロジェクトの雛形作成・パッケージインストールも含む）
- インターン向けの day01〜day30 のような教材記事執筆（詳細設計確定後の別工程）
- インフラ（本番デプロイ環境）の構築
