## 着手後にこのファイルへ記載する内容（目次予定）

1. テスト方針（ユニット/結合/E2Eの範囲分担）
2. 機能要件（`01_要件定義書.md`）ごとのテスト観点一覧
3. E2E のシナリオ一覧（Expo の web 出力に対する Playwright を想定。Phase 1 で確定）
4. **実機でしか確認できない項目の手動確認手順** — `02_技術選定書.md` §5 の R5 で
   明記した通り、カメラ権限ダイアログ・**ディープリンクからのアプリ起動**など
   自動E2Eの対象外となる項目の一覧と確認手順を明文化する
5. **RLS ポリシーの検証方法**（別ユーザーのトークンで他人の行を読み書きしようとして
   拒否されることを確かめる。旧目次の「パスワードハッシュ化の検証」は
   Supabase Auth の責務になったため消滅 — `01_要件定義書.md` §3 参照）
6. G6実走環境の定義（DB初期状態・起動/リセット手順・秘密情報・OS別 — Codex R1 M7対応）
7. モバイル試験基準（対応OS範囲・権限拒否・オフライン・再接続・購入者のWindows環境の扱い — Codex R1 M23対応）
8. アクセシビリティ受入基準（対象画面・基準値 — Codex R1 m5対応）
9. タイムライン取得の性能目安と測定条件（データ量・試行回数・パーセンタイル — Codex R1 m4対応）。
   **旧「ローカル開発環境で200ms以内」は前提ごと消滅**したため、目安値の再定義（16 B23）を
   受けてから測定条件を書く。**DB 側の実行時間と利用者の体感時間を分けて測る**こと、
   リージョンと回線条件を固定することを条件に含める（2026-07-27 の別ファミリーレビュー指摘）
10. **メール系の検証**（FR13 メール確認・FR14 パスワード再発行のトークン期限と到達確認。
    Supabase 標準の1時間2通制限に当たらないテスト手順を含む — 16 B14 と連動。
    2026-07-26 の C-4 決定により新設）
11. **組版成果物（PDF / EPUB）の検査観点**（2026-08-06 新設。
    `decisions/D23_Vivliostyle採用の影響.md`）。組版の失敗は exit code に出ない型が
    実測で複数見つかっているため、観点をここに置かないと着手時点で落ちる。
    最低限: 本文に記法の文字列（`embedmd` 等）が残っていないこと／目次の章順が
    章分割表と一致すること／コードブロックが1本の段落に潰れていないこと／
    長いコード行が版面外で切り落とされていないこと（原稿のコード各行が成果物のテキストに
    含まれるかの照合）／リンク宛先に `localhost` が焼き付いていないこと／
    ビルドログの `ERROR 404` がゼロであること。
    **検査の層を分けること**: 28本＋G3/G5 は Markdown 原稿にのみ走らせ、PDF には走らせない
    （PDF はバッククォートと行の構造を失うので、既存の文字列検査が偽陰性を出す — 実測）。
    リンク列挙は `pdftotext` では取れず `pdftohtml` が要る。
    **CI に `poppler-utils` を入れる手当ては未検証**。検査を作るかの決定は 16 B53
