# Phase 0 承認パッケージ（2026-07-28 提出）

## 承認してほしいこと

**Phase 0（計画固め）の文書一式を承認し、Phase 1（詳細設計）へ進む許可をください。**

承認の対象は**14文書**です。下の表では、判断のまとまりごとに**10行**へ束ねてあります
（最後の2行はそれぞれ3文書ずつをまとめています）。「10行まとめて承認」と答えた場合は
14文書すべての承認として扱います。判断が要る箇所は各行の「承認するのはここ」に絞ってあります。
**全文を読む必要はありません。** 表の右端「これを承認すると何が決まるか」だけ見て、
引っかかる行があればそこだけ本文を開いてください。

承認・差し戻しは行単位で構いません（「02 だけ差し戻し」のような形で大丈夫です）。

1. **04 詳細設計書**に着手（着手条件＝03の承認）
2. **06 API設計書**に着手（着手条件＝03と05の承認）。

   - **B14**: メール送信の上限を実測する。何アカウント作れるかが分からないと、
     複数アカウントを使う章を設計できません
   - **捨て試作を SDK 54 で作り直す**（16 §B-P0）。いまの捨て試作は SDK 57 で作られており、

   **4 の2件が終わるまで凍結しません。**先に凍結すると、上限に当たった時点で
   章の並びごとやり直しになります

差し戻しの場合、**「差し戻された文書だけ直せば済む」とは限りません。**

文書には上下があります。02（技術選定）が変われば 03（画面）も 05（DB）も前提から
変わります。上流が差し戻されたのに下流をそのまま進めると、**すでに崩れた前提の上で
Phase 1 を始めることになります。**

- 差し戻しが **01 または 02 または 03 または 05** の場合: それより下流の文書を止めて、
  影響の有無をこちらで洗い直してから再提出します。影響が無いと確認できた文書だけ進めます。
  **01（要件定義）が最上流です。**05 は「01 の機能要件をカバーするテーブル定義」と
  自ら定義しているので、01 が変われば 05 も 03 も前提から変わります
- 差し戻しが **上記以外**（00・07・09〜16）の場合: その文書だけ直して再提出し、他は止めません
- どちらの場合も、**止めた文書と止めなかった文書の一覧を再提出時に示します**
