**このディレクトリはまだ空である。受領証は1本も無い。**

## なぜ空のまま置いてあるか

`material/decisions/D15_G4受領証の様式と発注手順.md` が、この決定と同じPRで
このファイルを置いてディレクトリを実在させることを求めている。
`curriculum/README.md` と同じ理由で、**ディレクトリが無い間は「記録が無い」のか
「置き場が無い」のかを機械が区別できない**ためである。

## ここに何を置くか

| 何 | 置き場 |
|---|---|
| 章ごとの G4 受領証 | `material/reviews/g4/<章ID>.md`（1章1ファイル。D15-1） |
| 様式 | `material/reviews/_template_G4受領証.md` |

## 検査が見るもの（D15）

1. このディレクトリ直下の `.md` の basename が、章分割表（`material/18-chapter-split-table.md`）の
   **生きている章ID集合に含まれること**
2. 教材PRの対象章に受領証が**存在すること**（`test -f material/reviews/g4/<章ID>.md`）

2026-09-24 に両方を実装した。D15-8 の残りの項目（記入漏れ、観点3行、§3.1 の回答、
ラウンド数、総合判定）と、D15-6 のファミリーの確認も同じ検査が見る。
ラウンド一覧の行や `# R<n>` の節が重複していれば違反にする。重複で4回目のラウンドを隠せないようにするためである。
検査は `scripts/curriculum-qa/check_g4_receipt.py`、CI は `.github/workflows/gates.yml` の
「G4 受領証の検査」である。PR では、差分で追加・変更・改名された `curriculum/<章ID>.md` の受領証を要求する（改名は新しいIDとして数える）。

受領証が0件の今は「未判定」（終了コード3）で終わる。D1 §8-3 のとおり、0件を合格とは扱わない。
章分割表は DRAFT / NON-G1 のままなので、章IDの集合は凍結前の表から読んでいる。

## このディレクトリは文体ゲートの対象外である

`.claude/hooks/material-writing-gate.sh` は `curriculum/` しか見ていない。
受領証は記録であって教材本文ではないため、この扱いで正しい。
