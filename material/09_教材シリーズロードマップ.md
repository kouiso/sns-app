# 09. 教材シリーズロードマップ「TypeScript Everywhere」

ステータス: 提案（局長への叩き台）

## コンセプト

「TypeScriptという1つの言語を身につければ、Web・モバイル・デスクトップ・
ターミナル・ブラウザ拡張まで、あらゆるプラットフォームで開発者として通用する」
ことを、実際に動くクローンアプリを通じて段階的に体感させるシリーズ。

各教材は毎回「新しいプラットフォームへの挑戦」を1つだけ追加し、
バックエンド（NestJS）側の知識は極力使い回すことで、学習者が
「増分」に集中できるように設計する。

## シリーズ全体の並び（提案）

| 順 | 教材 | 新しく学ぶプラットフォーム | 題材アプリ | 前作からの再利用 |
|---|---|---|---|---|
| 1 | 本教材（sns-app） | Web + Capacitor（iOS/Android ハイブリッド） | SNS（Twitterモドキ） | task-appのReact基礎、Prisma |
| 2 | デスクトップ版チャットアプリ | Tauri または Electron（デスクトップネイティブシェル） | Slackモドキ（チーム内チャット） | sns-appのNestJS+WebSocket基盤をチャット用に転用 |
| 3 | 開発者向けCLIツール | Node.js CLI + Ink（ターミナル上でReactを描画） | GitHub CLI風のタスク/Issue管理CLI | 同バックエンドAPIをCLIから叩く |
| 4 | ブラウザ拡張機能 | Chrome拡張（Manifest V3）+ React | ページ要約・クリッパーツール | 同バックエンド、認証フローの再利用 |
| 5 | 真のネイティブモバイル | React Native（Native）+ TanStack Start（Web/サーバー側）+ NestJS（Capacitorとの対比） | カメラ・位置情報を使うInstagramモドキ | sns-appとの比較で「ハイブリッド（技術要素少）vs ネイティブ（技術要素多）」を体感 |
| 6 | リアルタイムダッシュボード | React + WebSocket + NestJS Gateway（実機材不要） | スマートホーム風の架空デバイス監視ダッシュボード | sns-appの通知基盤をテレメトリ通知に転用 |

## 並び順の設計意図

1. **#1→#2**: Webのその場での配信（Capacitor）から、OSに常駐するデスクトップアプリへ。
   「配信の入れ物」が変わる感覚を学ぶ
2. **#2→#3**: GUIを一切持たないCLIという極端な形式に触れることで、
   「UIがなくてもTypeScriptで価値あるツールが作れる」ことを学ぶ
3. **#3→#4**: 再びGUIに戻るが、今度はブラウザという「ホストアプリケーションに
   寄生する」形式のプラットフォーム制約を学ぶ
4. **#4→#5**: ここで初めて「真のネイティブ」に挑戦する。#1のCapacitor体験と
   意図的に比較させることで、ハイブリッドとネイティブのトレードオフを
   身をもって理解させる（`02_技術選定書.md`で先送りにした対比がここで回収される）
5. **#5→#6**: 最後に、フロントエンドの見た目に頼らない「リアルタイム性そのもの」を
   主役にした教材で締める。物理デバイスを持たないインターンでも
   架空デバイスのシミュレータで学べるようにする

## 未検討・要局長判断の論点

- 各教材の想定期間（本教材のようにウォーターフォールで作るか、
  前作のように30日間ハンズオン形式で作るか）は教材ごとに再検討が必要
- #2以降を着手するタイミングは、本教材（#1）が実装・教材化まで完了してから
  改めて計画フェーズを回す（本ロードマップは方向性の合意のみが目的）
