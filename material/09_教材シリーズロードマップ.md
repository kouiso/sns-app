# 09. 教材シリーズロードマップ「TypeScript Everywhere」

ステータス: 提案（局長への叩き台）
改訂: 2026-07-26。第1弾の構成が Expo + Supabase へ変わったのに伴い、並びを組み直した。
**ボツにした Capacitor + React + Vite + TanStack Router の検討内容は捨てず、第2弾の素材として
本書に移した**（経緯は `02_技術選定書.md`）。

## コンセプト

「TypeScript という1つの言語を身につければ、モバイル・Web・サーバー・デスクトップ・
ターミナル・ブラウザ拡張まで、あらゆるプラットフォームで開発者として通用する」
ことを、実際に動くクローンアプリを通じて段階的に体感させるシリーズ。

各教材は毎回「新しく学ぶこと」を1つだけ足し、それ以外は前作から使い回すことで、
学習者が**増分に集中できる**ように設計する。

### 使い回す土台は「Supabase のバックエンド」

第1弾で作る Supabase のデータベース（テーブル定義と RLS）を、**第2弾ではそのまま使う**。
これにより「フロントエンドだけ差し替える」構図を、同じ題材で体験できる。

**第3弾は「そのまま」ではない**（2026-07-27 の別ファミリーレビューで判明）。
第1弾のアプリは Supabase の SDK を直接呼んでおり、認証もデータ取得もリアルタイムも
その SDK の形をしている。バックエンドを NestJS と自前の認証に置き換えると、
**呼び出し方そのものが変わる**ため「フロントは1行も変えない」は成立しない。
第3弾で再利用するのは**画面と、アプリの中の考え方**であり、
**データの取り方と認証の部分は書き換える**。その書き換えこそが第3弾で学ぶ中身になる。

## シリーズ全体の並び（提案）

| 順 | 教材 | 新しく学ぶこと | 題材アプリ | 前作からの再利用 |
|---|---|---|---|---|
| 1 | **本教材（sns-app）** | Expo（React Native）でのモバイル開発 ＋ Supabase（RLS・認証・Realtime・Storage） | SNS（Twitterモドキ） | task-app の React 基礎 |
| 2 | **Web 版 SNS（別スタック）** | React + Vite + TanStack Router で、素の Web アプリを組む | 同じ SNS を Web 専用に作り直す | **第1弾の Supabase をそのまま使う**（バックエンドは1行も変えない） |
| 3 | **サーバーを自分で作る** | NestJS + PostgreSQL/Prisma + JWT + Redis + BullMQ | 同じ SNS のバックエンドを自作に置き換える | **第1弾のアプリの画面を使う**（データの取り方と認証は書き換える。§上記） |
| 4 | デスクトップ版チャットアプリ | Tauri または Electron（デスクトップネイティブシェル） | Slackモドキ（チーム内チャット） | 第3弾の自作バックエンドをチャット用に転用 |
| 5 | 開発者向け CLI ツール | Node.js CLI + Ink（ターミナル上で React を描画） | GitHub CLI 風のタスク/Issue 管理 CLI | 同じバックエンドを CLI から叩く |
| 6 | ブラウザ拡張機能 | Chrome 拡張（Manifest V3）+ React | ページ要約・クリッパーツール | 同じバックエンド、認証フローの再利用 |
| 7 | リアルタイムダッシュボード | WebSocket を主役にした設計（実機材不要） | スマートホーム風の架空デバイス監視 | 第3弾の通知基盤をテレメトリ通知に転用 |

## 第2弾・第3弾の位置づけ（2026-07-26 に確定した部分）

第1弾から派生する2本だけは、方向性が確定している。以下はその根拠。

### 第2弾: Web 版 SNS（別スタック）

**「同じバックエンドに、違うフロントエンドを繋ぐ」を体験する教材。**
実務で最も頻出する構図であり、第1弾の Supabase をそのまま使えるため制作コストが低い。

扱う内容:
- React + Vite + TanStack Router（第1弾の Expo Router と対比する）
- ブラウザの `div` / `span` と、React Native の `View` / `Text` の違い
- **Expo の web 出力で作る Web と、素の React で作る Web は何が違うのか**

**第1弾から Web パートを抜かない理由**（局長「二本立てにしようかな」への回答）:
シリーズの看板は「1つの言語でどこでも作れる」。Web パートを第1弾から外すと、
**第1弾だけを買った人は看板を一度も体験せずに読み終わる**。看板を証明する部分が
本編に無い商品は、その看板を掲げられない。加えて Expo は web 出力を標準で持つため、
同じコードで Web を出すだけなら分量が薄く、単体では売り物にならない。
→ 第1弾にはパートD（Web でも同じものが動く）を置き、第2弾は**別スタック**で厚みを出す。

### 第3弾: サーバーを自分で作る（NestJS）

**第1弾で「Supabase に任せた部分」を、全部自分の手で作り直す教材。**
局長発言「だったら NestJS の教材とか作れそう」の回収先であり、
`00_企画概要.md` が第1弾から外した「サーバーまで自分で作れる」をここで満たす。

扱う内容（第1弾でボツにした検討内容がそのまま素材になる）:
- NestJS + PostgreSQL + Prisma
- 自前の JWT + リフレッシュトークン（第1弾では Supabase Auth に任せた部分）
- パスワードのハッシュ化（bcrypt）— 第1弾の非機能要件から外した学習
- Redis / BullMQ による非同期ジョブ・通知のファンアウト
- MinIO（S3互換ストレージ）と Docker Compose での一括起動
- REST + OpenAPI による API 仕様の設計

**この並びの教育的な強み**: 学習者は第1弾で「Supabase がやってくれていたこと」を
既に使い倒しているため、第3弾では**何を作るのかが最初から分かっている**状態で始められる。
いきなりサーバーフレームワークを学ぶより動機が保てる。

## 並び順の設計意図

1. **#1→#2**: バックエンドを固定してフロントエンドだけ差し替える。
   「同じデータに違う画面を繋ぐ」という実務の基本形
2. **#2→#3**: 今度はフロントエンドを固定してバックエンドを差し替える。
   #1・#2 で使ってきた Supabase の中身が、自分の手で再現できると分かる
3. **#3→#4**: 「配信の入れ物」を変える。ブラウザでもスマホでもなく、
   OS に常駐するデスクトップアプリへ
4. **#4→#5**: GUI を一切持たない CLI という極端な形式に触れ、
   「UI が無くても TypeScript で価値あるツールが作れる」ことを学ぶ
5. **#5→#6**: 再び GUI に戻るが、今度はブラウザという
   「ホストアプリケーションに寄生する」形式のプラットフォーム制約を学ぶ
6. **#6→#7**: 最後に、見た目に頼らない「リアルタイム性そのもの」を主役にした教材で締める。
   物理デバイスを持たないインターンでも架空デバイスのシミュレータで学べるようにする

### 旧ロードマップから消えた項目

旧 #5「真のネイティブモバイル（React Native）」は**消滅**した。
第1弾が Expo（React Native）になったため、「ハイブリッド vs ネイティブの対比を
後の教材で回収する」という前提そのものが無くなったため。
その対比のうち生き残る論点（Expo の web 出力 vs 素の React）は第2弾へ移した。
