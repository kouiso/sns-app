## 1. 対象ユーザー

- エンドユーザー（教材内の想定ユーザー）: SNSに投稿・閲覧・交流したい一般利用者
- 学習者（実際の利用者）: プログラミング未経験〜初級のインターン

## 2. 機能要件

| ID | 機能 | 概要 |
|---|---|---|
| FR1 | 認証 | 新規登録・ログイン（**メールアドレス＋パスワード**で認証。usernameは表示ID/プロフィールURL用でログインには使わない — Codex R2 MAJOR11で確定）・ログアウト。**Supabase Auth が担う**（セッションとトークンの更新は Supabase 側の責務。自前の JWT 実装は行わない） |
| FR2 | プロフィール | 表示名・自己紹介・アイコン画像・ヘッダー画像の表示と編集 |
| FR3 | 投稿（ポスト） | 本文（最大280文字）＋画像最大4枚。投稿の削除 |
| FR4 | タイムライン | フォロー中ユーザーの投稿を新着順に無限スクロール表示 |
| FR5 | リプライ | 投稿への返信、スレッド（会話）表示 |
| FR6 | リポスト | 無言リポストと引用リポスト（コメント付き） |
| FR7 | いいね | 投稿へのいいね、いいね数の表示 |
| FR8 | フォロー関係 | フォロー / フォロー解除、フォロー一覧・フォロワー一覧の表示 |
| FR9 | 通知 | いいね・リプライ・リポスト・フォロー時の**アプリ内**リアルタイム通知（**Supabase Realtime**）。アプリを閉じている間のOSプッシュ通知（APNs/FCM）はスコープ外（下表参照）。自前の WebSocket サーバーは作らない |
| FR10 | 検索 | キーワードによる投稿検索・ユーザー検索 |
| FR11 | ハッシュタグ | 投稿本文からのハッシュタグ抽出、ハッシュタグ別一覧表示 |
| FR12 | ブックマーク | 投稿を自分だけの一覧に保存 |

| FR13 | メールアドレス確認 | 新規登録時に確認メールを送り、メール内のリンクを開いて初めて利用可能にする。**モバイルではディープリンク（メール内のリンクからアプリを開く仕組み）の実装が要る**（局長決定 2026-07-26 / C-4） |
| FR14 | パスワード再発行 | パスワードを忘れた場合に、メール経由で再設定できる（Supabase Auth の `resetPasswordForEmail`。局長決定 2026-07-26 / C-4） |
| FR15 | ネイティブ機能 | 端末のカメラで撮影して投稿に画像を添付する（FR3 のモバイル拡張）。局長方針「native の機能が簡単に作れればいい」に対応 |

※ FR13・FR14 は 2026-07-26 の局長決定（C-4）による追加。FR15 は Codex R2 MINOR6 の
「ネイティブ機能1点を FR として明記する」に対する確定（構成が Expo になり、
カメラが `expo-camera` で実現できることが確定したため Phase 1 を待たず確定した）。

### スコープ外（本教材では扱わない）

明示的に対象外とする。理由は「教材の学習効果に対して実装コストが見合わない」
「安全性・法務上の配慮が必要で初心者向け教材の範囲を超える」のいずれか。

| 対象外機能 | 対象外にする理由 |
|---|---|
| ダイレクトメッセージ（DM） | E2E暗号化やスレッド管理の複雑さが学習目的に対して過大 |
| 広告配信 | ビジネスロジックが本題（SNS技術）から逸れる |
| 通報・自動モデレーション | 濫用対策は本番運用が前提の機能であり、教材の安全な範囲を超える |
| 多言語対応（i18n） | UI国際化はテーマが分散するため対象外。日本語UI固定 |
| 動画のトランスコーディング | メディア処理の学習は静止画で代替、動画は将来教材の候補（09参照） |
| OSプッシュ通知（APNs/FCM） | 端末トークン管理・証明書設定など運用色が強く、アプリ内通知（Supabase Realtime）で学習目的は満たせるため（Codex R1 M17対応）。将来教材の候補 |

## 3. 非機能要件

| 区分 | 要件 |
|---|---|
| 想定規模 | 教材用途につき小規模（同時接続 〜100程度）を想定。ただし設計自体は将来スケールしても破綻しない形にする（ページネーション戦略を教材内で扱うため）。Supabase 無料枠は DB 500MB / RAM 500MB |
| セキュリティ | **パスワードのハッシュ化・ログインのレート制限・セッション管理は Supabase Auth の責務**とし、自前で実装しない（bcrypt を自分で書く学習は第3弾の NestJS 教材へ移した）。代わりに本教材では **RLS（行レベルセキュリティ）を学習者が自分で書く** — 「他人の投稿を消せない」「非公開の行が読めない」を DB 自身に守らせる。画像アップロードはMIMEタイプ・拡張子・サイズを検証。XSS対策として投稿本文は表示時にエスケープ |
| パフォーマンス | **目安値は再定義中（16 B23）**。旧「ローカル開発環境で200ms以内」は、自前のAPIサーバーが手元で動いていた頃の前提であり、データの取得先がホスト型の Supabase になった今は再現できない（端末・Wi-Fi・Supabase のリージョン・開発モード・Realtime の接続状態に左右される）。測り方を **DB 側の実行時間**と**利用者の体感時間**に分けたうえで、リージョンと回線条件を固定した端末実測値へ置き換える（2026-07-27 の別ファミリーレビュー指摘。測定条件は `08_テスト計画書.md` で定義 — Codex R1 m4対応） |
| 可用性 | 単一環境での稼働を前提とし、冗長化・障害復旧は対象外（学習目的のため） |
| アクセシビリティ | 前作 `task-app` 同様、基本的なキーボード操作とコントラスト比に配慮する |

## 4. 前提・制約

- 学習者の前提知識は**不要**（単体でも始められる — 局長決定 2026-07-24）。
  序盤にTypeScript基礎パートを新規執筆で内包する（文体は局長制作済みの
  対話形式教材をスタイルの正本とする）。
  経験者はスキップできる導線を用意する（詳細: `11_ターゲット・ペルソナ・UX定義.md`）
- 本教材はモバイル（iOS/Android）配信を含むが、**学習者に Xcode / Android Studio の
  セットアップは要求しない**。Expo Go（スマホに入れるアプリ）で QR コードを読むだけで
  自分の実機に画面が出る（2026-07-26 の構成変更により、旧構成が「最大の挫折ポイント」と
  していた工程が消えた。詳細は `02_技術選定書.md` §2）
- Supabase 標準のメール送信には2つの制限がある。**先に効くのは宛先のほう**（2026-07-28 決着・16 §B14）。
  - **組織のメンバーとして登録したアドレスにしか送らない。** 演習用に適当なアドレスで
    アカウントを作っても、**1通目から届かない**
  - 通数は1時間に2通（プロジェクト全体の合計）
  - **決定**: メール確認は学習者本人のアドレス1つで教え、複数アカウントが要る章は
    メール確認を切って進める。カスタム SMTP は教材の必須手順にしない

## 5. 用語集

| 用語 | 説明 |
|---|---|
| ポスト（Post） | 投稿。いわゆる「ツイート」に相当する本教材内の呼称 |
| リポスト（Repost） | 他者の投稿を自分のタイムラインに転載する操作（いわゆる「リツイート」） |
| タイムライン | フォロー中ユーザーの投稿を集約した一覧 |
| Expo Go | スマホに入れておくと、QR コードを読むだけで開発中のアプリをその端末で動かせるアプリ |
| RLS（行レベルセキュリティ） | 「誰がどの行を読み書きできるか」を DB 自身に守らせる仕組み。アプリ側の書き忘れがあっても DB が拒否する |
| ディープリンク | メールや他アプリのリンクを開いたときに、ブラウザではなく目的のアプリが開く仕組み |
