# 12. 文体・AI臭さ排除方針

ステータス: ドラフト（局長レビュー待ち）
局長決定事項（2026-07-24）: 文体は「実際に先生と生徒が教え合っているスタイル」。
正本は局長制作済みのTS基礎教材（Google Drive: 変数と定数〜クラス、磯貝×阿部対話形式）。

## 1. 正本教材から抽出した文体スペック

局長の既存教材（「変数と定数_第3稿」「関数_第2稿」等を実際に読んで分析）から、
以下を本教材の文体スペックとして凍結する。

### 1.1 形式: 話者ラベルつき対話台本

```
磯貝）まず、文法における一番最初の概念として、変数と定数というものがあります。
阿部）はい。よろしくお願いします。
```

- 話者ラベルは「名前）」形式（全角閉じ括弧）で行頭に置く
- 地の文は原則使わない。説明はすべて先生のセリフとして書く
- 見出し・コードブロック・図表は対話の外に通常のMarkdown要素として置く

### 1.2 先生（磯貝）のセリフの特徴

| 特徴 | 実例（正本より） |
|---|---|
| です・ます調ベース＋自然な口語混じり | 「じゃあ何で"let"で書くんだって話になりそうだけど」 |
| 具体物への例え | 変数=「箱」、再代入=「りんごを出してオレンジを入れる」 |
| 手を動かさせる指示 | 「これを実行してみましょう。Runボタンをクリックしてみてください」 |
| 出力結果を一緒に確認 | 「"りんご"、"りんご"って出ましたね」 |
| 難しい背景は気楽に流す | 「ちょっと難しい話だから、ああそうなんだという程度で読んでください」 |
| 覚えるべき用語は明示 | 「用語として頭に入れておいてください」 |

### 1.3 生徒（阿部）の4つの役割

生徒は相槌要員ではない。以下の役を果たす（1・2・4は全章必須、3は開発ログ連動の
条件つき — Codex R3 MINOR4対応）:

1. **質問する**: 学習者が抱く疑問を代弁する
2. **誤答する**: もっともらしい間違いをして、先生が正す（例: 呼び出す関数を取り違える）
3. **エラーを踏む**（条件つき — Codex R1 M10対応）: 開発ログ（10 §5）に「教材に載せる価値: 高」の
   詰まりがある章のみ。無い章では架空のエラーを創作せず、質問・誤答・復唱で構成する
4. **復唱まとめ**: 章末に学んだことを自分の言葉で要約し、先生が補足・確認する

### 1.4 章構成（正本のパターンを踏襲）

1. 章タイトル＋「この章でできるようになること」
2. 対話で概念導入（例え話→コード実行→出力確認）
3. 生徒のエラー体験→先生と解決（開発ログに実例がある章のみ — M10対応）
4. 生徒の復唱まとめ→先生の締め
5. 演習問題（正本と同じく本文と対で用意する。解答は別掲）

## 2. AI臭さ排除規則（前作PR #266事件の再発防止）

前作では誇大・情緒的・トレーラー調のAI文体が混入し、局長から
「こういう誇大表現みたいなもの、やめてくれ」という直接苦情に至った（491行削除の書き直し）。
本作では以下を**執筆開始前から機械ゲートで**禁止する。

### 2.1 禁止表現カテゴリ

| カテゴリ | 例（すべて禁止） |
|---|---|
| 誇大・煽り | 「ついに」「いよいよ真の」「〜する日です！」「魔法のような」 |
| 情緒・詩的 | 「本当に外へ出るのだから」「かなり気持ちいい日」「ちょっと自慢してよい」 |
| AI構文 | 「〜と言えるでしょう」「重要なのは〜という点です」の乱発、箇条書き全太字の並列構造 |
| 英語直訳調 | 「〜することができます」の乱発（→「〜できます」）、「それでは〜していきましょう」の機械的反復 |
| 関西弁・タメ口 | 教材本文では全面禁止（前作で混入→35ファイル一括変換の原因） |
| 記号 | 教材本文で絵文字禁止。強調は太字のみ |

### 2.2 対話形式ならではの追加規則

- 生徒のセリフを「はい」「なるほど」だけの相槌にしない（4役割のどれかを果たす）
- 先生のセリフ1つを272文字以内目安（正本の最長実測値）。超えるなら生徒の相槌ではなく
  **意味のある応答**を挟んで分割する
- 話者ラベルの整合: 「磯貝）」「阿部）」以外の話者を登場させない（ラベル表記ゆれ禁止）

## 3. 機械ゲート化（10_教材制作フローのG2/G3と接続）

1. **check_tone.py移植版**: task-appで完成済みの文体チェッカー（関西弁・AI構文・
   誇大表現・英語直訳調を行番号つき検出、exit 1）をsns-app用に移植
2. **対話形式チェッカー（新規）**: 話者ラベルの形式・登場人物の限定・生徒セリフの
   相槌率（「はい。」系のみの行が生徒セリフの50%を超えたらFAIL）・章構成要素の存在を機械検査
   （復唱まとめ・演習は全章必須。**エラー体験は開発ログに「価値: 高」エントリがある章のみ必須**
   — ログと連動させ、実例の無い章には要求しない。Codex R2 MAJOR2対応）
3. 両ゲートとも、既知の陽性サンプル（前作PR #266で削除された誇大文）と
   陰性サンプル（正本教材の抜粋）で検知テストしてから有効化（10のG0条件）
